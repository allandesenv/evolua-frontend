## Key architecture proposal
Generate random 256-bit DEK per local profile; never derive it from Google subject/email, PIN or password. Device-bound wrapping key in Android Keystore/iOS Keychain (non-exportable where platform supports); separate local credential-derived wrapping layer and portable recovery envelope with independent credential. Require local authentication policy (biometrics optional and device-auth bounded); do not equate possession of secure storage entry with authenticated user. Use platform security hardware when available and describe fallback honestly. Store only wrapped keys and versioned metadata; no plaintext keys/passwords in prefs, logs, backups, telemetry or temporary files. No Google/email reset can decrypt the private journal without recovery credential/backup. Password change rewraps DEK, does not revoke previously exported copies. Wrong credential fails before opening SQLCipher; plugin documents automatic Android cipher_migrate on older formats, must explicitly investigate current implementation and avoid triggering it on original DB. Fail closed on missing keys, mismatched profile, unavailable secure storage, corrupted metadata; no automatic new DB or silent key regeneration for existing profile. No immutable memory erasure guarantees in Dart; minimize copies/lifetime. Backup/restore authenticate metadata and payload, bounded format parsing, staged validation, explicit confirmation and atomic publication; no plaintext restore intermediates. Revoke session generation on lock/logout/profile switch, close database, discard caches and reject stale completion. Existing auth untouched. Device loss and unrecoverable credentials explained clearly.

## S3A scope
Test-only synthetic envelope, cryptography 2.9.0 (existing lock), AES-256-GCM, Argon2id fixed candidate 19456 KiB, 2 iterations, 1 lane, 16-byte random salt and 32-byte output. OWASP minimum candidate, not final tuning; measure mobile KDF and memory before setting policy. Worker isolate; no external service. AAD binds version/profile/purpose and KDF parameters. Eight tests covering DEK, independent recovery, wrong password/profile/purpose, salt/tag tamper, rewrap and independence from Google. No persistence or production key implementation, no dependency changes, no new APK. No assertions of secure storage, native key protection or backup format from these tests. Next S3B native device key store + KDF calibration and backup exclusion, then explicit adoption decision; EVP-02 identity design.
